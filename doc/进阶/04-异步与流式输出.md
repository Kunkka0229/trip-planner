# P4：全链路异步 + 流式输出

> **需求卡片**
> 埋点数据显示：生成一份行程平均 40 秒，**35% 的用户在 20 秒内关掉了页面**。用户访谈里最多的一句话是"我以为卡死了"。
> 另外，压测发现 10 个用户同时生成行程时，服务就开始排队了。
> 本迭代：**① 让用户在等待中看到"行程一天一天长出来"；② 用户关掉页面后立即停止生成，不再白花钱；③ 一个进程能同时服务更多用户。**

**目标**：把整条链路从"同步 + 线程"改成"异步（asyncio）"，用 LangGraph 的 `astream` + 自定义事件推送逐天草稿。学完你会掌握：同步和异步代码在 FastAPI 里的区别、"把 IO 和逻辑分开"的重构方法、异步限速、流式解析不完整的 JSON、`get_stream_writer` 和 `subgraphs=True`、SSE 心跳和断线取消。

> 本课代码用**真实的 uvicorn 服务 + 一个每 50 毫秒吐一段字的假模型**验证过：① 生成过程中请求 `/health` 只要 8 毫秒（没有被阻塞）；② 心跳正常发送；③ 客户端断开后，大模型的流式调用被立即取消（`CancelledError`），一段字都没有再生成。

## 先搞清楚：同步、线程、异步

你基础课一直用 `def` 写路由（第 5 课的表格）。FastAPI 对 `def` 路由的处理是：**放到线程池里执行**。线程池默认 40 个线程，每个请求占一个线程，等高德、等大模型的时候，这个线程就干等着。

| | 同步 `def` + 线程池（基础课） | 异步 `async def`（本课） |
|---|---|---|
| 等待 IO 时 | 线程阻塞，干等 | 让出控制权，事件循环去处理别的请求 |
| 同时能处理的请求数 | ≈ 线程数（默认 40） | 几千个（只要都在等 IO） |
| 每个请求的开销 | 一个线程（约 8MB 栈内存） | 一个协程（几 KB） |
| 写法要求 | 随便写 | **所有 IO 都必须是异步的**，混进一个同步阻塞调用就会卡住所有请求 |
| 前端类比 | 每个请求开一个 Web Worker | 浏览器主线程上的 `async/await` |

一次行程生成里 95% 的时间都在等（等高德、等大模型），这正是异步最擅长的场景。

> 公司里 Agent 服务几乎都是异步的：LangChain、LangGraph、OpenAI SDK、httpx 都提供了异步接口（`ainvoke`、`astream`、`AsyncClient`），MCP 工具甚至**只**支持异步。第 8 课那个"常驻后台事件循环 + `run_coroutine_threadsafe`"的绕路方案，根源就是"同步路由里要调用异步工具"。路由本身变成异步之后，直接 `await` 就行了，那个绕路方案不再需要（见本课末尾"回看第 8 课"）。

## Step 1：异步高德客户端 `app/services/amap_client.py`（整个文件替换）

先说一个**你代码里的 bug**：`get_amap_client` 上面的注释写着"用 lru_cache 实现单例"，但你漏写了 `@lru_cache`（第 5 课讲义里有）。后果是每个请求都会新建一个 `AmapClient`，每个客户端各自限速，**第 9 课加的限速实际上没有生效**，并发一高还是会触发高德的 QPS 超限。这次一起修掉。

```python
"""高德地图 Web 服务 API 客户端（直接走 HTTP，不经过大模型）

官方文档：https://lbs.amap.com/api/webservice/summary
本课用到两个接口：
  - 关键字搜索 POI：GET /v3/place/text
  - 天气查询：    GET /v3/weather/weatherInfo

P4：同时提供同步（search_poi）和异步（asearch_poi）两套方法，和 LangChain 的 invoke / ainvoke 一个思路
  - 请求参数的拼装、响应的解析是纯函数，两套方法共用（"把 IO 和逻辑分开"）
  - 只有"发请求"这一步分成同步和异步两种写法
"""

import asyncio
import threading
import time
from functools import lru_cache
from typing import Any

import httpx  # Python 的 HTTP 客户端，API 风格和 axios 很像；装 fastapi[standard] 时已经带上了

from app.config import get_settings
from app.models.schemas import Location, POIInfo, WeatherInfo

# 高德地图 Web 服务 API 的基础 URL
AMAP_BASE_URL = "https://restapi.amap.com/v3"


class AmapError(Exception):
    """高德调用失败时抛出的业务异常（自定义异常类，相当于 JS 的 class AmapError extends Error）"""


def parse_location(text: Any) -> Location | None:
    """高德返回的坐标是字符串 "116.397,39.909"（经度在前），转成 Location 对象"""
    if not isinstance(text, str) or "," not in text:
        return None  # 有些 POI 没有坐标，或者返回的是 []
    lng, lat = text.split(",", 1)
    try:
        return Location(longitude=float(lng), latitude=float(lat))
    except ValueError:
        return None


def parse_float(value: Any) -> float | None:
    """高德的 rating/cost 可能是 "4.6"、""、[]，统一转成 float 或 None"""
    try:
        return float(value)
    except (ValueError, TypeError):
        return None


def as_text(value: Any) -> str:
    """高德的一个坑：字段没有值时，返回的不是 "" 而是 []，统一转成字符串"""
    return value if isinstance(value, str) else ""


# ---------- 纯函数：参数拼装和响应解析（同步、异步共用）----------

def poi_params(keyword: str, city: str, limit: int) -> dict[str, Any]:
    return {
        "keywords": keyword,
        "city": city,
        "citylimit": "true",  # 只在指定城市内搜索
        "extensions": "all",  # 返回详细信息（包括评分、人均消费）
        "offset": limit,  # 每页条数
        "page": 1,
    }


def parse_pois(data: dict[str, Any]) -> list[POIInfo]:
    results: list[POIInfo] = []
    for poi in data.get("pois", []):
        location = parse_location(poi.get("location"))
        if location is None:
            continue  # 没坐标的 POI 没法在地图上显示，直接丢掉
        biz_ext = poi.get("biz_ext") or {}  # `or {}`：值为 None 或 [] 时用空字典兜底
        results.append(
            POIInfo(
                id=poi.get("id", ""),
                name=poi.get("name", ""),
                type=as_text(poi.get("type")),
                address=as_text(poi.get("address")),
                district=as_text(poi.get("adname")),
                location=location,
                tel=as_text(poi.get("tel")),
                rating=parse_float(biz_ext.get("rating")),
                cost=parse_float(biz_ext.get("cost")),
            )
        )
    return results


def weather_params(city: str) -> dict[str, Any]:
    return {"city": city, "extensions": "all"}  # all = 预报，base = 实况


def parse_weather(data: dict[str, Any]) -> list[WeatherInfo]:
    forecasts = data.get("forecasts") or []
    if not forecasts:
        return []
    return [
        WeatherInfo(
            date=cast.get("date", ""),
            day_weather=cast.get("dayweather", ""),
            day_temp=cast.get("daytemp", "未知"),
            night_temp=cast.get("nighttemp", "未知"),
        )
        for cast in forecasts[0].get("casts", [])
    ]


def check_response(response: httpx.Response) -> dict[str, Any]:
    """高德的另一个坑：业务失败时 HTTP 状态码照样是 200，要看 body 里的 status"""
    data = response.json()
    if data.get("status") != "1":
        raise AmapError(f"高德返回错误: {data.get('info')}（infocode={data.get('infocode')}）")
    return data


def wrap_http_error(e: httpx.HTTPError) -> AmapError:
    """注意：不要直接写 f"{e}"！httpx 的异常信息里带着完整 URL，URL 里有 key=你的Key"""
    if isinstance(e, httpx.HTTPStatusError):
        return AmapError(f"请求高德失败: HTTP {e.response.status_code}")
    return AmapError(f"请求高德失败: {type(e).__name__}")


class AmapClient:
    def __init__(self, api_key: str, transport: httpx.MockTransport | None = None, qps_limit: float = 3):
        """
        api_key：高德 Web 服务 Key
        transport：只在测试时传入。httpx.MockTransport 同时支持同步和异步客户端
        qps_limit：每秒最多发几个请求（第 9 课），0 表示不限速（测试时用）
        """
        if not api_key:
            raise AmapError("AMAP_API_KEY 未配置，请在 backend/.env 中填写")
        self.api_key = api_key
        self.http = httpx.Client(base_url=AMAP_BASE_URL, timeout=10, transport=transport)
        # P4：异步客户端，相当于 axios 的异步版本。await self.ahttp.get(...) 等待期间，事件循环可以去处理别的请求
        self.ahttp = httpx.AsyncClient(base_url=AMAP_BASE_URL, timeout=10, transport=transport)

        # ---------- 限速（第 9 课，P4 改成"预约时间槽"的写法）----------
        self.min_interval = 1 / qps_limit if qps_limit > 0 else 0
        self._lock = threading.Lock()
        self._next_slot = 0.0  # 下一个可用的发送时间点

    def _reserve_wait(self) -> float:
        """预约一个发送时间槽，返回需要等待的秒数

        第 9 课的写法是"拿着锁睡觉"：time.sleep 在锁里面，异步代码不能这样做（会卡住整个事件循环）
        新写法：锁里只做一次很快的计算（预约下一个空闲时间点），睡觉放在锁外面。
        同步方法用 time.sleep 等，异步方法用 asyncio.sleep 等，两边共用同一个时间表
        """
        if self.min_interval <= 0:
            return 0.0
        with self._lock:
            now = time.monotonic()
            slot = max(now, self._next_slot)  # 最早能发的时间：现在，或者排在前面的人之后
            self._next_slot = slot + self.min_interval  # 下一个人至少要再等一个间隔
            return slot - now

    def _with_key(self, params: dict[str, Any]) -> dict[str, Any]:
        return {**params, "key": self.api_key}

    # ---------- 同步：给 poi / map 路由和旧的规划器用 ----------

    def _get(self, path: str, params: dict[str, Any]) -> dict[str, Any]:
        time.sleep(self._reserve_wait())
        try:
            response = self.http.get(path, params=self._with_key(params))
            response.raise_for_status()
        except httpx.HTTPError as e:
            raise wrap_http_error(e) from e
        return check_response(response)

    def search_poi(self, keyword: str, city: str, limit: int = 10) -> list[POIInfo]:
        return parse_pois(self._get("/place/text", poi_params(keyword, city, limit)))

    def get_weather(self, city: str) -> list[WeatherInfo]:
        return parse_weather(self._get("/weather/weatherInfo", weather_params(city)))

    # ---------- 异步（P4）：给 LangGraph 的异步节点用 ----------

    async def _aget(self, path: str, params: dict[str, Any]) -> dict[str, Any]:
        await asyncio.sleep(self._reserve_wait())  # asyncio.sleep 不会卡住事件循环，time.sleep 会
        try:
            response = await self.ahttp.get(path, params=self._with_key(params))
            response.raise_for_status()
        except httpx.HTTPError as e:
            raise wrap_http_error(e) from e
        return check_response(response)

    async def asearch_poi(self, keyword: str, city: str, limit: int = 10) -> list[POIInfo]:
        return parse_pois(await self._aget("/place/text", poi_params(keyword, city, limit)))

    async def aget_weather(self, city: str) -> list[WeatherInfo]:
        return parse_weather(await self._aget("/weather/weatherInfo", weather_params(city)))


# 整个进程共用一个客户端（连接池和限速的时间表都要共享），和 get_settings 一样用 lru_cache 实现单例
# P4 修复：之前漏了 @lru_cache，每个请求都会新建一个客户端，各自限速，等于没限速
@lru_cache
def get_amap_client() -> AmapClient:
    settings = get_settings()
    return AmapClient(settings.amap_api_key, qps_limit=settings.amap_qps_limit)
```

**要点**

1. **"把 IO 和逻辑分开"**（业界叫 sans-IO）。`poi_params`、`parse_pois`、`check_response` 都是纯函数：输入数据，输出数据，不发请求。同步方法和异步方法只有"发请求"那一行不同，其他全部共用。这样做还有一个好处：解析逻辑可以不借助任何假网络，直接用一个字典测试。
2. **限速改成"预约时间槽"**。第 9 课的写法是在锁里 `time.sleep`。在异步代码里这是大忌：`time.sleep` 会让整个事件循环停下来，所有用户的请求都跟着卡住。新写法在锁里只做一次很快的计算（"我排在几点几分发"），睡觉放到锁外面，异步方法用 `await asyncio.sleep(...)`，不会卡住别人。
3. **`httpx.MockTransport` 同时支持同步和异步客户端**，需要模拟高德返回时，同一个假 transport 两种客户端都能用。
4. 顺手删掉了 `AmapError` 类里那行多余的 `global _last_request_at`（第 9 课改限速时留下的，类定义里写 `global` 不会报错，但没有任何作用）。

```python
# ---------- P4：把"拿到数据之后怎么整理"抽成纯函数，同步和异步方法共用 ----------

def attraction_rows(request: TripRequest, poi_lists: list[list[POIInfo]]) -> dict[str, Any]:
    """poi_lists：每个偏好关键词各搜一次，得到多个列表"""
    pois: dict[str, POIInfo] = {}
    for poi_list in poi_lists:
        for poi in poi_list:
            pois.setdefault(poi.id, poi)  # setdefault：key 不存在才写入，实现按 id 去重并保留先出现的
    rows = []
    for poi in pois.values():
        price, source = ticket_price_hint(poi, request)
        rows.append(poi_row(poi, ticket_price_hint=price, price_source=source))
    return {"attraction_pois": rows}


def hotel_rows(request: TripRequest, pois: list[POIInfo]) -> dict[str, Any]:
    rows = []
    for poi in pois:
        price, source = hotel_cost_hint(poi, request)
        rows.append(poi_row(poi, estimated_cost_hint=price, price_source=source))
    return {"hotel_pois": rows}


def food_rows(pois: list[POIInfo]) -> dict[str, Any]:
    rows = []
    for poi in pois:
        price, source = meal_cost_hint(poi)
        rows.append(poi_row(poi, meal_cost_hint=price, price_source=source))
    return {"food_pois": rows}


def attraction_keywords(request: TripRequest) -> list[str]:
    return request.preferences[:3] or ["景点"]


class PlannerContextBuilder:
    def __init__(self, amap: AmapClient):
        self.amap = amap

    # ---------- 同步版：每个工具一个方法，返回 {字段名: 数据} ----------
    def collect_attractions(self, request: TripRequest) -> dict[str, Any]:
        lists = [self.amap.search_poi(kw, request.city, limit=10) for kw in attraction_keywords(request)]
        return attraction_rows(request, lists)

    def collect_hotels(self, request: TripRequest) -> dict[str, Any]:
        return hotel_rows(request, self.amap.search_poi(request.accommodation, request.city, limit=8))

    def collect_foods(self, request: TripRequest) -> dict[str, Any]:
        return food_rows(self.amap.search_poi("美食", request.city, limit=20))

    def collect_weather(self, request: TripRequest) -> dict[str, Any]:
        return {"trip_weather": align_weather(request, self.amap.get_weather(request.city))}

    # ---------- 异步版（P4）：给 LangGraph 的异步节点用 ----------
    async def acollect_attractions(self, request: TripRequest) -> dict[str, Any]:
        # asyncio.gather：同时发出多个请求，等全部完成，相当于 Promise.all
        # * 把列表展开成多个参数：gather(a, b, c)
        lists = await asyncio.gather(
            *(self.amap.asearch_poi(kw, request.city, limit=10) for kw in attraction_keywords(request))
        )
        return attraction_rows(request, list(lists))

    async def acollect_hotels(self, request: TripRequest) -> dict[str, Any]:
        return hotel_rows(request, await self.amap.asearch_poi(request.accommodation, request.city, limit=8))

    async def acollect_foods(self, request: TripRequest) -> dict[str, Any]:
        return food_rows(await self.amap.asearch_poi("美食", request.city, limit=20))

    async def acollect_weather(self, request: TripRequest) -> dict[str, Any]:
        return {"trip_weather": align_weather(request, await self.amap.aget_weather(request.city))}

    # ---------- 并行执行所有工具 ----------
    def collect(self, request: TripRequest) -> dict[str, Any]:
        ...（不变）
```

## Step 3：异步的 collect 子图 `app/graph/collect.py`

改三处：`TOOLS` 换成异步方法、节点改成 `async def`、节点里用 writer 发出"工具结果"事件。

```python
"""collect 子图：4 个工具节点并行调高德，再汇总成 PlannerContext

        ┌→ attractions ┐

START ──┼→ foods       ┼→ assemble → END

import logging
from typing import Annotated, Any, Awaitable, Callable, TypedDict

def merge_dict(old: dict, new: dict) -> dict:
    """reducer：把新字典合并进旧字典。4 个并行节点各自返回一部分，最后拼成一个完整的字典"""

class CollectState(TypedDict, total=False):

    # （InvalidUpdateError：同一步里有多个节点更新了同一个字段，它不知道该听谁的）
    snapshot: Annotated[dict[str, Any], merge_dict]
    tool_status: Annotated[dict[str, Any], merge_dict]
    context: dict[str, Any]


class CollectInput(TypedDict):

# 工具名 → PlannerContextBuilder 上的方法
# PlannerContextBuilder.acollect_hotels 是"未绑定方法"，调用时要手动传 self：func(builder, request)
# P4：换成异步版本（acollect_xxx），返回值是协程，要 await
TOOLS: dict[str, Callable[[PlannerContextBuilder, TripRequest], Awaitable[dict[str, Any]]]] = {
    "attractions": PlannerContextBuilder.acollect_attractions,
    "hotels": PlannerContextBuilder.acollect_hotels,
    "foods": PlannerContextBuilder.acollect_foods,
    "weather": PlannerContextBuilder.acollect_weather,
}


def make_tool_node(name: str, func: Callable):
    """工厂函数：为每个工具生成一个节点函数（4 个节点逻辑一样，只是调的方法不同）"""

    # runtime: Runtime[PlannerDeps]：LangGraph 看到这个参数名和类型，会自动把运行时依赖注入进来
    # P4：async def。4 个异步节点在同一步里并发执行（asyncio，不再需要线程）
    async def node(state: CollectState, runtime: Runtime[PlannerDeps]) -> dict[str, Any]:
        # get_stream_writer：拿到"自定义事件"的发送函数，发出去的事件会出现在 stream_mode="custom" 里
        # 调用方没订阅 custom 时，writer 什么也不做，所以节点里可以放心地调用
        writer = get_stream_writer()
        builder = PlannerContextBuilder(runtime.context.amap)
        try:
            result = await func(builder, state["request"])
        except Exception as exc:
            # 和第 9 课一样：失败只记录在 tool_status 里，不影响其他工具
            logger.warning("工具 %s 失败: %s", name, exc)
            writer({"type": "tool", "name": name, "ok": False})
            return {"tool_status": {name: {"ok": False, "error": str(exc)}}}
        count = len(next(iter(result.values())))
        writer({"type": "tool", "name": name, "ok": True, "count": count})  # 前端可以显示"✅ 景点 12 个"
        return {"snapshot": result, "tool_status": {name: {"ok": True, "count": count}}}

    return node


def assemble(state: CollectState) -> dict[str, Any]:
    """4 个工具都结束后执行（成功或失败都算结束）：组装成完整的 PlannerContext"""
    request = state["request"]
    # empty_snapshot 打底：失败的工具没有写 snapshot，对应字段保持空值
    snapshot = empty_snapshot(request) | state.get("snapshot", {})
    return {"context": assemble_context(request, snapshot, state.get("tool_status", {}))}


def build_collect_graph():
    # input_schema / output_schema：对外只暴露 request（入）和 context（出），
    # snapshot、tool_status 是子图内部的"私有状态"，不会泄漏到主图
    builder = StateGraph(
        CollectState,
        context_schema=PlannerDeps,
        input_schema=CollectInput,
        output_schema=CollectOutput,
    )
    for name, func in TOOLS.items():
        builder.add_node(name, make_tool_node(name, func))
        builder.add_edge(START, name)  # START 连出 4 条边 = 4 个节点在同一步并行执行（fan-out）
    builder.add_node("assemble", assemble)
    # 第一个参数是列表：等列表里的节点全部执行完，才执行 assemble（fan-in，相当于 Promise.all 之后）
    builder.add_edge(list(TOOLS), "assemble")
    builder.add_edge("assemble", END)
    return builder.compile()
```

**`get_stream_writer()` 是本课的核心 API**。节点除了"返回 state 的更新"，还可以随时往外发送任意事件。调用方用 `stream_mode="custom"` 接收。没人订阅时（比如 P3 的评测用 `ainvoke`），writer 什么也不做，节点代码不用判断。

## Step 4：流式生成 `app/graph/trip_graph.py`

`generate` 节点改成异步 + 流式；`validate` 和 `fallback` 各加一行进度事件。

```python
"""规划主图：把第 7、9 课的"收集 → 生成 → 校验 → 重试 / 兜底"画成一张状态图

START → collect ──有景点──→ generate ──有输出──→ validate ──通过──→ END
           │                  ↑   │                │
           │                  │   └──调用失败──┐   │ 不通过
           │                  └────还能重试────┴───┘
           │                                   │ 次数用完
           └──没有景点──────→ fallback ←────────┘ → END
"""

import json
import logging
from typing import Any, Literal

from langchain_core.messages import HumanMessage, SystemMessage
from langchain_core.utils.json import parse_partial_json
from langgraph.config import get_stream_writer
from langgraph.graph import END, START, StateGraph
from langgraph.runtime import Runtime

from app.agents.generation import BASE_TEMPERATURE, MAX_ATTEMPTS, build_fallback
from app.agents.output import parse_and_check, recompute_budget
from app.agents.prompts import PLANNER_SYSTEM_PROMPT, build_context_prompt
from app.graph.collect import build_collect_graph
from app.graph.state import PlannerDeps, TripState
from app.models.schemas import WeatherInfo
from app.planner.context import compact_for_prompt
from app.planner.grounding import ground_plan

logger = logging.getLogger(__name__)


def error_reason(exc: Exception) -> str:
    """异常 → 一行简短的原因（和第 7 课 generate_plan_with_retries 里的写法一样）"""
    return f"{type(exc).__name__}: {str(exc).splitlines()[0]}"


# ---------- 节点：每个节点接收 state，返回"要更新的字段" ----------

def finished_days(text: str) -> list[dict[str, Any]]:
    """P4：从还没生成完的 JSON 里，解析出已经"写完"的那几天

    parse_partial_json 能解析不完整的 JSON（自动补齐缺失的括号和引号），例如
        '{"days": [{"date": "a"}, {"date": "b", "mea'  →  {"days": [{"date": "a"}, {"date": "b"}]}
    最后一天可能还没写完，所以只返回"后面已经开始写下一天"的那些天
    """
    start = text.find("{")
    if start == -1:
        return []
    try:
        data = parse_partial_json(text[start:])
    except Exception:  # 前面有不规范的内容，暂时解析不了，等更多内容到达再试
        return []
    days = data.get("days") if isinstance(data, dict) else None
    return days[:-1] if isinstance(days, list) else []


async def generate(state: TripState, runtime: Runtime[PlannerDeps]) -> dict[str, Any]:
    """调用一次大模型，只负责拿到原始输出，不做校验

    P4：改成流式调用。模型每吐出一段文字就检查一次，有一天写完了，就立刻把这一天推给前端
    用户在 30 秒的等待里能看到行程一天一天地"长出来"，而不是盯着进度条
    """
    writer = get_stream_writer()
    attempt = state.get("attempts", 0) + 1
    context_json = json.dumps(compact_for_prompt(state["context"]), ensure_ascii=False, separators=(",", ":"))
    prompt = build_context_prompt(context_json, state["request"].travel_days)
    if errors := state.get("errors"):
        prompt += f"\n\n注意：上一次的输出不合格，原因是：{errors[-1]}。请修正后重新输出完整 JSON。"
        writer({"type": "reset"})  # 重试：让前端清掉上一次的草稿
    writer({"type": "progress", "stage": "正在生成行程" if attempt == 1 else f"正在重新生成（第 {attempt} 次）",
            "percent": 40 + 10 * (attempt - 1)})

    temperature = BASE_TEMPERATURE + 0.1 * (attempt - 1)
    messages = [SystemMessage(PLANNER_SYSTEM_PROMPT), HumanMessage(prompt)]
    parts: list[str] = []
    sent = 0  # 已经推送了几天
    try:
        # astream：异步流式调用，每次产出一小段（chunk），相当于前端用 fetch 读 ReadableStream
        async for chunk in runtime.context.llm.astream(messages, temperature=temperature):
            parts.append(chunk.text)
            if "}" not in chunk.text:  # 只有出现右括号时，才可能有一天刚写完，省掉大部分解析
                continue
            days = finished_days("".join(parts))
            for index in range(sent, len(days)):
                writer({"type": "day", "index": index, "day": days[index]})
            sent = max(sent, len(days))
    except Exception as exc:  # 超时、网络错误：记一次失败，draft 置空
        logger.warning("第 %d/%d 次调用失败: %s", attempt, MAX_ATTEMPTS, error_reason(exc))
        return {"attempts": attempt, "draft": "", "errors": [error_reason(exc)]}
    return {"attempts": attempt, "draft": "".join(parts)}


def validate(state: TripState) -> dict[str, Any]:
    """校验 + grounding + 天气覆盖 + 预算重算（原来 context_planner 里 postprocess 闭包做的事）"""
    request, context = state["request"], state["context"]
    try:
        plan = parse_and_check(state["draft"], request)
        stats = ground_plan(plan, context)
        plan.weather_info = [WeatherInfo(**w) for w in context["tool_snapshot"]["trip_weather"]]
        plan.budget = recompute_budget(plan, request)
    except Exception as exc:
        logger.warning("第 %d/%d 次校验失败: %s", state["attempts"], MAX_ATTEMPTS, error_reason(exc))
        return {"errors": [error_reason(exc)]}

    logger.info("Grounding: 景点命中率 %.0f%%，未匹配 %s", stats["attraction_rate"] * 100, stats["ungrounded"])
    get_stream_writer()({"type": "progress", "stage": "校验通过", "percent": 90})
    status = context["tool_status"]
    warnings = [f"{name} 数据获取失败" for name, s in status.items() if not s["ok"]]
    warnings += [f"{name} 不在高德候选中" for name in dict.fromkeys(stats["ungrounded"])]
    return {"plan": plan, "source": "llm", "warnings": warnings}


def fallback(state: TripState) -> dict[str, Any]:
    request = state["request"]
    get_stream_writer()({"type": "progress", "stage": "智能规划失败，使用基础行程", "percent": 90})
    if state.get("attempts", 0) == 0:  # 一次都没调用大模型，说明是景点数据缺失
        error = state["context"]["tool_status"].get("attractions", {}).get("error", "没有搜到景点")
        reason = f"景点数据获取失败: {error}"
        return {"plan": build_fallback(request, reason), "source": "fallback", "errors": [reason]}
    logger.error("大模型多次生成失败，返回兜底方案")
    return {"plan": build_fallback(request, "大模型多次生成失败"), "source": "fallback"}


# ---------- 路由函数：读 state，返回下一个节点的名字 ----------
# 返回值类型写成 Literal：LangGraph 会据此知道"可能去哪些节点"，画图时能画出所有分支

def route_start(state: TripState) -> Literal["collect", "generate", "fallback"]:
    """P3：调用方已经带了 context（评测时用冻结的 context）就跳过 collect，直接进入后面的流程"""
    return route_after_collect(state) if state.get("context") else "collect"


def route_after_collect(state: TripState) -> Literal["generate", "fallback"]:
    # 景点是行程的核心：没有景点候选就不调用大模型（第 9 课的规则）
    return "generate" if state["context"]["tool_snapshot"]["attraction_pois"] else "fallback"


def retry_or_give_up(state: TripState) -> Literal["generate", "fallback"]:
    return "generate" if state["attempts"] < MAX_ATTEMPTS else "fallback"


def route_after_generate(state: TripState) -> Literal["validate", "generate", "fallback"]:
    return "validate" if state["draft"] else retry_or_give_up(state)


def route_after_validate(state: TripState) -> Literal["generate", "fallback", "__end__"]:
    # "__end__" 就是 END 常量的值；plan 存在说明校验通过
    return END if state.get("plan") else retry_or_give_up(state)


def build_trip_graph():
    builder = StateGraph(TripState, context_schema=PlannerDeps)
    # 编译好的子图可以直接当成一个节点：主图只看到它的输入（request）和输出（context）
    builder.add_node("collect", build_collect_graph())
    builder.add_node("generate", generate)
    builder.add_node("validate", validate)
    builder.add_node("fallback", fallback)

    # P3：入口也可以是条件边。正常请求走 collect；评测时传入冻结的 context，直接去 generate
    builder.add_conditional_edges(START, route_start)
    # 条件边：执行完 collect 后，调用 route_after_collect，按返回值决定去哪
    # 相当于前端路由守卫：beforeEach((to) => hasData ? next() : next('/fallback'))
    builder.add_conditional_edges("collect", route_after_collect)
    builder.add_conditional_edges("generate", route_after_generate)
    builder.add_conditional_edges("validate", route_after_validate)
    builder.add_edge("fallback", END)
    return builder.compile()


# 图的结构是固定的，模块加载时编译一次，所有请求共用（依赖通过 context 每次传入）
trip_graph = build_trip_graph()
```

**要点**

1. **为什么不直接把 token 推给前端（打字机效果）？** 因为模型输出的是 JSON，用户看到 `{"days":[{"date":"2026-` 在屏幕上一个字一个字地蹦，毫无意义。对结构化输出，正确的做法是**流式解析**：边收边解析，每"完成"一个有意义的单元（这里是一天的行程），就推给前端渲染。ChatGPT 的"边想边写"、Cursor 的"边生成边显示 diff"都是这个思路。
2. **`parse_partial_json`**：LangChain 自带的工具，能解析不完整的 JSON（自动补齐括号和引号）。最后一天可能刚写到一半，所以 `finished_days` 只返回"后面已经出现下一天"的那些天。最后一天要等完整输出、校验通过后，随最终结果一起发出。
3. **草稿 ≠ 最终结果**。推送的是**未经校验**的草稿：价格还没被 hint 覆盖，可能有编造的景点。前端要明确标成"草稿"（灰色、骨架屏样式），收到最终结果后整体替换。如果校验失败要重试，先发一个 `reset` 事件让前端清空草稿。
4. **小优化**：只有收到的片段里有 `}` 时才去解析（一天写完必然以 `}` 结尾），避免每收到一个字都把整段文本重新解析一遍。

```python
"""LangGraph 版规划器（P1 创建，P4 改成异步 + 事件流）

P4 之后，路由只通过这里调用规划图。旧的规划器（direct / context / multi_agent）不再被路由使用
"""

from typing import Any, Callable

from app.agents.generation import PlanResult
from app.graph.state import PlannerDeps, TripState
from app.graph.trip_graph import trip_graph
from app.models.schemas import TripRequest
from app.observability.tracing import langchain_callbacks

# 事件回调：每产生一个事件（进度、工具结果、一天的草稿……）就调用一次
# 取代第 11 课的 ProgressFn(stage, percent)：事件不止"进度"一种了，统一用字典表示，靠 type 区分
EmitFn = Callable[[dict[str, Any]], None]


def no_emit(event: dict[str, Any]) -> None:
    """默认回调：什么都不做（和第 11 课的 no_progress 一样）"""


async def plan_with_graph(request: TripRequest, deps: PlannerDeps, emit: EmitFn = no_emit) -> PlanResult:
    emit({"type": "progress", "stage": "正在查询景点、酒店、餐厅和天气", "percent": 10})
    final: TripState = {}
    config = {"callbacks": langchain_callbacks(), "run_name": "trip_graph", "recursion_limit": 20}
    # astream：stream 的异步版本，用 async for 遍历
    #   "custom"：节点里 get_stream_writer() 发出的事件，原样转发给调用方
    #   "values"：每一步之后的完整 state，最后一次就是最终结果
    # P1 用来推进度的 "updates" 不需要了：节点自己在开始时就能发进度，比"结束后才知道"更及时
    # subgraphs=True：子图（collect）里发出的事件也要。不加的话，子图内部的事件不会出现在外层的流里
    #   加了之后每次产出变成三元组 (namespace, 模式, 数据)，namespace 表示事件来自哪一层：
    #   () 是主图，("collect:<id>",) 是 collect 子图
    async for namespace, mode, chunk in trip_graph.astream(
        {"request": request}, config=config, context=deps, stream_mode=["custom", "values"], subgraphs=True
    ):
        if mode == "custom":
            emit(chunk)
        elif namespace == ():  # 只要主图的 state；子图的 state 里没有 plan
            final = chunk
    emit({"type": "progress", "stage": "完成", "percent": 100})
    return PlanResult(
        plan=final["plan"],
        source=final["source"],
        attempts=final.get("attempts", 0),
        errors=final.get("errors", []),
        warnings=final.get("warnings", []),
    )
```

**`subgraphs=True` 是本课最容易踩的坑**：默认情况下，`astream` 只转发主图的事件，collect 子图里 writer 发出的"工具结果"事件会被丢掉，你会发现前端怎么也收不到。加上 `subgraphs=True` 后，每次产出变成三元组，多了一个 `namespace` 告诉你事件来自哪一层。

```python
    #   消费者：stream 生成器从队列里取事件，发给浏览器
    # asyncio.Queue 不是线程安全的，但这里两边都在同一个事件循环里，不需要线程安全
    events: asyncio.Queue[dict | None] = asyncio.Queue()

    async def worker() -> None:
        try:
            response = await run_planner(request, deps, user_id, emit=events.put_nowait)
            events.put_nowait({"type": "result", "data": response.model_dump(mode="json")})
        except Exception as exc:
            logger.exception("规划失败")
            events.put_nowait({"type": "error", "message": str(exc)})
        finally:
            events.put_nowait(None)

    # create_task：把 worker 放到事件循环里"后台"运行，立刻返回一个 Task 对象（相当于不 await 的 Promise）
    # create_task 会自动复制当前的 ContextVar，request_id 不会丢（对比 P2：自己开线程时要手动 copy_context）
    task = asyncio.create_task(worker())

    async def stream() -> AsyncIterator[str]:
        try:
            while True:
                try:
                    # 最多等 HEARTBEAT_SECONDS 秒；超时说明这段时间没有事件（大模型在慢慢生成）
                    event = await asyncio.wait_for(events.get(), timeout=HEARTBEAT_SECONDS)
                except TimeoutError:
                    # 心跳：以冒号开头的行是 SSE 注释，浏览器会忽略它
                    # 作用是让连接上一直有数据流过，避免被 Nginx、负载均衡器当成空闲连接断开（常见默认 60 秒）
                    yield ": ping\n\n"
                    continue
                if event is None:
                    break
                yield sse(event)
        finally:
            # 浏览器断开连接时，Starlette 会取消这个生成器，执行到 finally
            # 如果规划还没结束，就取消它：正在进行的大模型请求会被中断，不再继续花钱
            if not task.done():
                task.cancel()
                logger.info("客户端已断开，取消规划任务")

    return StreamingResponse(
        stream(),
        media_type="text/event-stream",
        headers={"Cache-Control": "no-cache", "X-Accel-Buffering": "no"},
    )


@router.post("/feedback", summary="对生成的行程打分（👍 / 👎）")
def submit_feedback(body: FeedbackRequest):
    ok = score_trace(body.trace_id, "user_feedback", 1 if body.helpful else 0, body.comment, data_type="BOOLEAN")
    return {"success": ok, "message": "感谢反馈" if ok else "未启用 Langfuse，反馈未记录"}
```

**要点**

1. **结构和第 11 课一模一样**：生产者 + 队列 + 消费者。只是线程换成了 `asyncio.create_task`，`queue.Queue` 换成了 `asyncio.Queue`。理解了第 11 课，这里就没有新东西。
2. **断线取消是怎么发生的**：浏览器关掉页面 → TCP 连接断开 → Starlette 发现后取消 `stream()` 生成器 → 执行 `finally` → `task.cancel()` → 正在 `await` 的大模型请求收到 `CancelledError`，HTTP 连接被关闭，模型供应商那边停止生成（大部分供应商按实际生成的 token 计费）。第 11 课作业 2 问的就是这个问题，在同步版本里很难做到，异步版本是自然而然的。
3. **心跳**：大模型生成第一天之前可能有十几秒没有任何事件。很多代理（Nginx 默认 `proxy_read_timeout 60s`、云厂商的负载均衡器）会把"一段时间没有数据"的连接当成死连接断开。每 15 秒发一行 `: ping`，SSE 规范规定冒号开头的行是注释，浏览器会忽略。
4. **`logger.exception`**：和 `logger.error` 一样，但会把完整的异常堆栈也打印出来，只能在 `except` 块里用。

## Step 9：评测改成异步 `evals/`

图里有了异步节点，就不能再用同步的 `invoke` 了（会报错：`No synchronous function provided to "foods"`）。

`evals/judge.py`：`judge_plan` 改成 `async def`，调用改成：

```python
    # P4：改成异步，评测主程序用 asyncio 并发跑用例
    response = await llm.ainvoke([SystemMessage(JUDGE_SYSTEM_PROMPT), HumanMessage(user)], temperature=0)
    text = response.text
```

`evals/run.py`：`run_case` 改成 `async def`，里面的 `trip_graph.invoke` 改成 `await trip_graph.ainvoke`，`judge_plan` 前面加 `await`；`make_llm` 里也加上 `stream_usage=True`；线程池换成 `asyncio.Semaphore`：

```python
async def run_all(cases: list[dict[str, Any]], llm: BaseChatModel, judge_llm: BaseChatModel | None,
                  variant: str, workers: int) -> list[dict[str, Any]]:
    """P4：用 asyncio 并发跑用例（取代线程池）。Semaphore 限制同时在跑的用例数，避免被模型供应商限流"""
    semaphore = asyncio.Semaphore(workers)

    async def limited(case: dict[str, Any]) -> dict[str, Any]:
        async with semaphore:  # 同一时刻最多 workers 个用例拿到"通行证"，其余的在这里排队
            return await run_case(case, llm, judge_llm, variant)

    # gather 按传入的顺序返回结果，相当于 Promise.all(cases.map(limited))
    return list(await asyncio.gather(*(limited(c) for c in cases)))
```

`main` 里原来线程池的那三行换成：

```python
    rows = asyncio.run(run_all(cases, llm, judge_llm, args.variant, args.workers))
```

> `asyncio.run` 在整个评测程序里**只调用一次**。不要在 `run_case` 里各自 `asyncio.run`：那会给每个用例创建一个新的事件循环，又会遇到第 8 课的 "bound to a different event loop" 错误（ChatOpenAI 的异步连接池绑定在第一个事件循环上）。

## Step 10：亲手验证

1. **不阻塞**：开两个终端，一个用前端生成行程，生成过程中在另一个终端反复执行 `curl http://127.0.0.1:7001/health`，应该瞬间返回。把 `trip.py` 里的 `async def plan_trip` 临时改成调用一个 `time.sleep(10)` 的函数，再试一次，体会"一个同步阻塞调用卡住整个服务"是什么感觉。
2. **断线取消**：从前端生成行程，在"正在生成行程"时关掉页面，后端日志应该出现"客户端已断开，取消规划任务"，Langfuse 里这条 trace 的 generate 节点显示为取消/报错。
3. **用 curl 看事件流**：

```bash
curl -N -X POST http://127.0.0.1:7001/api/trip/plan/stream \
  -H 'Content-Type: application/json' \
  -d '{"city":"北京","start_date":"2026-11-06","end_date":"2026-11-08","travel_days":3,"preferences":["历史文化"],"party":{"adults":2}}'
```

`-N` 关闭 curl 的缓冲，能看到事件一条条到达：4 个 `tool` → `progress 40` → 若干 `day` → `progress 90` → `progress 100` → `result`。

## 前端改动（做到这一课时让我直接生成）

SSE 事件格式（每条都是 `data: {...}\n\n`，另有 `: ping` 心跳行，前端解析时跳过即可）：

| type | 字段 | 前端怎么用 |
|---|---|---|
| `progress` | `stage`, `percent` | 进度条 + 当前阶段文字（和第 11 课一样） |
| `tool` | `name`, `ok`, `count?` | 加载页显示一个清单："✅ 景点 12 个 ✅ 酒店 8 个 ❌ 天气获取失败" |
| `day` | `index`, `day`（未校验的一天） | 加载页下方逐天渲染**草稿卡片**（灰色、标注"草稿"） |
| `reset` | 无 | 清空草稿卡片（模型输出不合格，正在重试） |
| `result` | `data`（`TripPlanResponse`） | 跳转结果页，用正式数据替换草稿 |
| `error` | `message` | 显示错误 |

另外：用户点"取消"按钮或离开加载页时，用 `AbortController` 中止 fetch（后端会自动停止生成）。

## 回看第 8 课：异步之后，常驻事件循环就不需要了

第 8 课的 `MultiAgentTripPlanner.plan` 是这样的：

```python
    def plan(self, request, on_progress=no_progress) -> PlanResult:
        future = asyncio.run_coroutine_threadsafe(self._aplan(request, on_progress), get_background_loop())
        return future.result()
```

之所以这么绕，是因为路由是同步的 `def`，而 MCP 工具只能 `await`。现在路由已经是 `async def`，在 FastAPI 的事件循环里直接 `await planner._aplan(request, ...)` 就行，`get_background_loop` 可以整个删掉。"bound to a different event loop" 的问题也自然消失了：整个服务只有 uvicorn 创建的那**一个**事件循环。

**教训**：一个系统里最好只有一种并发模型。同步和异步混用时，边界处总会出现各种绕路方案。

## 常见问题

| 现象 | 原因 |
|---|---|
| `TypeError: No synchronous function provided to "foods". Either initialize with a synchronous function or invoke via the async API` | 图里有异步节点，却用了同步的 `invoke` / `stream` |
| 前端收不到 `tool` 事件 | `astream` 没加 `subgraphs=True` |
| 服务在生成行程时，其他接口也变慢了 | 异步路由里混进了同步阻塞调用（`time.sleep`、同步的 httpx、同步的 `llm.invoke`） |
| Langfuse 成本、评测 token 全是 0 | 没开 `stream_usage=True` |
| `RuntimeError: ... bound to a different event loop` | 在一个进程里多次 `asyncio.run`，共享的异步客户端跨了事件循环 |
| 通过 Nginx 访问时进度一次性全部到达 | Nginx 缓冲了响应，检查 `X-Accel-Buffering: no` 和 `proxy_buffering off` |
