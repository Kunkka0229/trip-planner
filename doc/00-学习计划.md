# Trip Planner 从 0 到 1 学习计划

> 学习方式：老师带教。每节课一个小目标，代码由你亲手敲，做完作业再进入下一课。
> 参考答案：`helloagents-trip-planner/`（参考仓库）+ [Hello-Agents 第 13 章](https://hello-agents.datawhale.cc/#/./chapter13/第十三章%20智能旅行助手)
> 你的项目：`backend/`、`frontend/`（本目录下），课程笔记都放在 `doc/`

## 背景：书 vs 参考仓库

参考仓库比书中的第 13 章更新，两者的设计差异是这个项目最值得学的地方：

| | 书中第 13 章 | 参考仓库现状 |
|---|---|---|
| Agent 结构 | 4 个 Agent：景点 / 天气 / 酒店 / Planner | 1 个 Planner `SimpleAgent`（类名仍叫 `MultiAgentTripPlanner`） |
| 数据获取 | 各 Agent 通过 MCP 调高德 | `PlannerContextBuilder` 用代码确定性地收集，主要走高德 HTTP API |
| 可靠性 | 依赖 prompt | 结构化上下文 + JSON 提取 + schema 校验 + grounding 检查 + 反馈重试 + fallback |
| 额外内容 | 无 | `training/`：SFT/DPO 后训练数据与评测 |

我们的路线：**先按书实现原始版本，再重构成仓库的现状**，亲身体会为什么要这样改。

**框架选择**：书和参考仓库用的是配套教学框架 hello-agents，本课程的 Agent 层换成了业界更通用的 **LangChain + LangGraph**（第 6 课起）。架构思路和书完全一样，只是写法不同，所以对照参考仓库时看"做了什么"，不要逐行对代码。

## 最终掌握标准

1. 不看代码，能讲清楚一次请求的完整数据流，以及每一层的职责。
2. 能独立用 FastAPI + Pydantic 写一个带校验、带文档、支持跨域的接口。
3. 能说清楚书中多 Agent 方案和仓库现方案各自的取舍：可控性、成本/延迟、可审计、幻觉、可训练。
4. 能列出 LLM 输出不可靠时，本项目的几道防线：结构化上下文 → prompt 约束 → JSON 提取 → schema 校验 → grounding 检查 → 反馈重试 → fallback。
