# P3：评测体系（Evals）

> **需求卡片**
> 同事提议把模型从 qwen 换成 DeepSeek，"便宜一半"。老板问你："换了以后质量会不会下降？"
> 你说"我试了几次感觉差不多"，老板不满意。
> 本迭代：**建立一套评测，用数字回答"A 和 B 哪个好、好多少、在哪些场景下更差"**。以后每次改 prompt、换模型、改流程，都先跑评测再上线。

**目标**：搭起 Agent 系统的"尺子"。学完你会掌握：评测集设计、冻结输入（控制变量）、规则评估器、LLM-as-judge 和它的坑、汇总指标（含延迟和成本）、两次评测的对比报告、在 CI 里设质量门槛。

> 本课代码在临时目录里测试过：新增 6 个测试，共 41 个全部通过。另外用假模型把命令行完整跑了一遍（`run` 生成结果文件 → `compare` 生成对比报告 → `--min-success` 退出码）。**没有用真实模型跑过 30 条用例**，所以讲义里没有给出"参考分数"，你跑出来的第一份结果就是你的基线。

## 评测 ≠ 测试

| | 测试（第 11 课） | 评测（本课） |
|---|---|---|
| 测什么 | 代码逻辑对不对 | 模型输出好不好 |
| 用不用真实模型 | 不用，用假模型 | 用 |
| 结果 | 通过 / 失败 | 分数（0~1），看趋势和对比 |
| 什么时候跑 | 每次提交 | 改 prompt、换模型、改流程之前；定期跑 |
| 花不花钱 | 不花 | 花（30 条用例，每条 1~3 次大模型调用） |

第 11 课结尾说过："至于大模型本身输出得好不好，那是评测要解决的问题。"这节课就来解决它。

## 评测体系的四个部分

```
评测集（30 条用例）──→ 冻结 context ──→ 跑规划图 ──→ 评估器打分 ──→ 汇总 / 对比报告
  dataset.jsonl     record_contexts.py    run.py      evaluators.py      compare.py
                                                       judge.py
```

### 1. 评测集：覆盖真实场景 + 边界情况

好的评测集不是"随便写 30 个城市"，而是**每一条都在测一个具体的能力**。看 `tags` 字段：

| 类别 | 例子 | 测什么 |
|---|---|---|
| 常规 | 北京 3 天历史文化 | 基本能力，大部分流量都是这种 |
| 预算 | 1500 元硬约束、20000 元高预算 | 预算约束是否被遵守 |
| 亲子 / 老人 | 带一岁宝宝、两位 70 岁老人 | 节奏是否适配同行人员 |
| 约束冲突 | 成都美食但"不能吃辣" | 能否处理和常识冲突的要求 |
| 冷门城市 | 景德镇、阿勒泰 | 高德候选少时会不会编造 |
| 边界 | 1 天、7 天、无偏好、预算 300 元 | 极端输入下会不会崩 |
| 安全 | 免费文本里写"忽略之前的所有规则" | prompt 注入（P11 会专门讲） |

> 线上跑起来之后，评测集最好的来源是**真实的失败案例**：用户点了 👎 的、Langfuse 里 level=WARNING 的，挑出来加进评测集。评测集是会"长大"的。

### 2. 冻结输入：控制变量

如果每次评测都重新调高德，今天和明天的搜索结果、天气都不一样，分数变了也分不清是模型的原因还是数据的原因。所以先把每个用例的 PlannerContext **收集一次存成文件**，之后所有评测都用这份固定的输入，唯一的变量就是你要比较的东西（模型、prompt）。

这是第 9 课 PlannerContext 设计带来的红利：它本来就是"格式固定的完整输入快照"。参考仓库 `training/` 目录里的"冻结评测集"做的也是这件事。

### 3. 评估器：规则优先，LLM 评委补充

| | 规则评估器 | LLM 评委 |
|---|---|---|
| 例子 | grounding 率、是否超预算、每天游览时长 | 路线顺不顺、符不符合"带婴儿"的需求 |
| 成本 | 免费、毫秒级 | 每条用例一次大模型调用 |
| 稳定性 | 完全确定 | 有随机性和偏差 |
| 原则 | **能用规则判断的，绝不交给 LLM** | 只评规则写不出来的东西 |

### 4. 汇总和对比

单个用例的分数波动很大，看的是**整体平均**和**逐用例的退步**。平均分涨了 2%，但有一个"带婴儿"的用例从 1.0 掉到 0.2，这种退步比平均分更值得关注。

## Step 1：让图可以跳过 collect `app/graph/trip_graph.py`

在 `route_after_collect` 的**上面**加一个路由函数：

```python
def route_start(state: TripState) -> Literal["collect", "generate", "fallback"]:
    """P3：调用方已经带了 context（评测时用冻结的 context）就跳过 collect，直接进入后面的流程"""
    return route_after_collect(state) if state.get("context") else "collect"
```

`build_trip_graph` 里把 `builder.add_edge(START, "collect")` 换成：

```python
    # P3：入口也可以是条件边。正常请求走 collect；评测时传入冻结的 context，直接去 generate
    builder.add_conditional_edges(START, route_start)
```

**这个改动在 P5 还会用到**：用户修改行程时，context 已经在上一次的 state 里了，不需要再调一遍高德。

```python
"""评测集的读取，以及冻结 context 的存取"""

import json
from pathlib import Path
from typing import Any

from app.models.schemas import TripRequest

EVALS_DIR = Path(__file__).resolve().parent
DATASET_PATH = EVALS_DIR / "dataset.jsonl"
CONTEXTS_DIR = EVALS_DIR / "contexts"  # 冻结的 PlannerContext，每个用例一个 JSON 文件
RESULTS_DIR = EVALS_DIR / "results"  # 每次评测的结果


def load_cases(ids: set[str] | None = None, tags: set[str] | None = None) -> list[dict[str, Any]]:
    """读取评测集。jsonl = 每行一个 JSON 对象，方便追加、方便 git diff 看出改了哪一条"""
    cases = []
    for line in DATASET_PATH.read_text(encoding="utf-8").splitlines():
        if not line.strip():
            continue
        case = json.loads(line)
        case["request"] = TripRequest.model_validate(case["request"])  # 评测集本身也要过校验，写错了立刻发现
        if ids and case["id"] not in ids:
            continue
        if tags and not tags & set(case["tags"]):  # & 是集合交集：有任意一个标签匹配就保留
            continue
        cases.append(case)
    return cases


def context_path(case_id: str) -> Path:
    return CONTEXTS_DIR / f"{case_id}.json"


def load_context(case_id: str) -> dict[str, Any] | None:
    path = context_path(case_id)
    return json.loads(path.read_text(encoding="utf-8")) if path.exists() else None
```

## Step 4：冻结 context `evals/record_contexts.py`

```python
"""冻结 PlannerContext：用真实高德把每个用例的 context 收集一次，存成文件

为什么要冻结？
  评测要回答的是"换了模型 / 改了 prompt，效果是变好还是变坏"。如果每次评测都重新调高德，
```

## Step 5：规则评估器 `evals/evaluators.py`

```python
"""规则评估器：每个函数检查行程的一个方面，返回 0~1 的分数；返回 None 表示"这一项不适用于这个用例"

规则评估器 = 确定性、免费、快。能用规则判断的，就不要交给 LLM 评委
"""

from collections import Counter
from dataclasses import dataclass
from typing import Any, Callable

from app.models.schemas import TripPlan, TripRequest
from app.planner.grounding import find_candidate


@dataclass
class CaseOutput:
    """一个用例跑完之后，评估器需要的全部信息"""

    request: TripRequest
    context: dict[str, Any]
    plan: TripPlan
    source: str  # "llm" | "fallback"
    attempts: int


def success(out: CaseOutput) -> float | None:
    """大模型成功生成（没有走兜底）"""
    return 1.0 if out.source == "llm" else 0.0


def first_try(out: CaseOutput) -> float | None:
    """第一次就生成成功。重试越多，延迟和成本越高"""
    if out.source != "llm":
        return None
    return 1.0 if out.attempts == 1 else 0.0


def grounding(out: CaseOutput) -> float | None:
    """景点、酒店、午晚餐中，能在高德候选里找到的比例。越低说明模型越爱编"""
    if out.source != "llm":
        return None
    snapshot = out.context["tool_snapshot"]
    total = matched = 0
    for day in out.plan.days:
        items = [(a.name, "attraction_pois") for a in day.attractions]
        if day.hotel:
            items.append((day.hotel.name, "hotel_pois"))
        items += [(m.name, "food_pois") for m in day.meals if m.type in ("lunch", "dinner")]
        for name, key in items:
            total += 1
            matched += find_candidate(name, snapshot[key]) is not None
    return matched / total if total else None


def budget_fit(out: CaseOutput) -> float | None:
    """有预算约束时：不超预算得 1 分；超了按超出比例扣分，硬约束超了直接 0 分"""
    constraint = out.request.budget_constraint
    if out.source != "llm" or constraint.amount is None or constraint.strictness == "none" or out.plan.budget is None:
        return None
    total, amount = out.plan.budget.total, constraint.amount
    if total <= amount:
        return 1.0
    if constraint.strictness == "hard":
        return 0.0
    return max(0.0, 1 - (total - amount) / amount)


def pace(out: CaseOutput) -> float | None:
    """节奏：每天游览总时长不超过上限的天数占比。带婴儿或儿童时上限更低"""
    if out.source != "llm":
        return None
    party = out.request.party
    limit = 300 if party.infants or party.children else 480  # 分钟
    ok_days = sum(sum(a.visit_duration for a in day.attractions) <= limit for day in out.plan.days)
    return ok_days / len(out.plan.days)


def meal_variety(out: CaseOutput) -> float | None:
    """同一天午餐和晚餐不是同一家的天数占比"""
    if out.source != "llm":
        return None
    ok_days = 0
    for day in out.plan.days:
        names = [m.name for m in day.meals if m.type in ("lunch", "dinner")]
        ok_days += len(names) == len(set(names))  # 有重复时 set 会变短
    return ok_days / len(out.plan.days)


def no_repeat_attractions(out: CaseOutput) -> float | None:
    """整个行程里景点不重复的比例（同一个景点安排两天，多半是候选不够、模型在凑数）"""
    if out.source != "llm":
        return None
    names = [a.name for day in out.plan.days for a in day.attractions]
    if not names:
        return None
    repeats = sum(count - 1 for count in Counter(names).values())
    return 1 - repeats / len(names)


def compact_route(out: CaseOutput) -> float | None:
    """每天的景点分布在不超过 2 个区县的天数占比（区县来自高德候选）"""
    if out.source != "llm":
        return None
    pois = out.context["tool_snapshot"]["attraction_pois"]
    ok_days = 0
    for day in out.plan.days:
        districts = {row["district"] for a in day.attractions if (row := find_candidate(a.name, pois))}
        ok_days += len(districts) <= 2
    return ok_days / len(out.plan.days)


# 名字 → 评估器。加一个新指标 = 写一个函数 + 在这里登记
EVALUATORS: dict[str, Callable[[CaseOutput], float | None]] = {
    "success": success,
    "first_try": first_try,
    "grounding": grounding,
    "budget_fit": budget_fit,
    "pace": pace,
    "meal_variety": meal_variety,
    "no_repeat_attractions": no_repeat_attractions,
    "compact_route": compact_route,
}


def evaluate(out: CaseOutput) -> dict[str, float | None]:
    return {name: func(out) for name, func in EVALUATORS.items()}
```

**要点**

1. **`None` 表示不适用，和 0 分完全不同**。没有预算约束的用例，`budget_fit` 是 `None`，汇总时会被跳过；如果写成 0 或 1，都会扭曲平均分。
2. **兜底方案只算 `success`**。兜底方案是代码生成的模板，拿它算 grounding、节奏没有意义，反而会把"模型质量"和"成功率"两件事混在一起。
3. **这些规则都很"粗糙"**：`pace` 只看游览时长，不看交通时间；`compact_route` 只看区县数量，不看实际距离。没关系，**评估器不需要完美，需要的是稳定、能反映趋势**。作业 2 让你加一个更精确的。
4. **为什么 `grounding` 和第 9 课的 `ground_plan` 重复了？** `ground_plan` 是线上流程的一部分，会修改行程；评估器只读不写，并且把酒店、餐厅也算进去。两者目的不同，评测代码不要依赖"线上流程算好的指标"，否则线上代码有 bug 时，评测也跟着一起错。

## Step 6：LLM 评委 `evals/judge.py`

```python
"""LLM-as-judge：让另一个大模型按评分标准（rubric）给行程打分

规则评估器只能检查"能写成代码的东西"。"这条路线顺不顺""符不符合带婴儿出行的需求"
这种需要常识和理解力的判断，交给 LLM 评委

LLM 评委的几个已知偏差，以及这里的应对：
  - 自我偏好：模型倾向于给自己（同一家族的模型）写的内容打高分 → 评委尽量用另一家的模型
  - 分数漂移：没有锚点时，"4 分"在不同调用里含义不同 → rubric 给每个分数写清楚标准
  - 长度偏好：越长的回答越容易被打高分 → 只给评委看精简后的行程，不给它看 description 长文
  - 随机性 → temperature=0，并且让它先写理由再打分
"""

import json

from langchain_core.language_models import BaseChatModel
from langchain_core.messages import HumanMessage, SystemMessage
from pydantic import BaseModel, Field

from app.models.schemas import TripPlan, TripRequest

JUDGE_SYSTEM_PROMPT = """你是严格的旅行行程评审专家。你会看到用户的需求和一份行程，请按下面的标准逐项打 1-5 分。

【route 路线合理性】
5 = 每天的景点在同一片区域，顺序顺路，没有来回折返
3 = 大体合理，有一天出现明显的跨城区折返
1 = 景点随意堆砌，完全不考虑距离

【preference_fit 偏好匹配】
5 = 偏好标签和额外要求（free_text_input）全部体现，必去点都安排了
3 = 体现了一部分偏好，有明显遗漏
1 = 基本无视用户偏好，或者违反了用户明确提出的要求（比如用户不吃辣却安排了火锅）

【party_fit 同行人员适配】
5 = 完全考虑了同行人员（婴儿、儿童、老人）的体力和需求，节奏合适
3 = 没有明显问题，但也没有专门考虑
1 = 明显不适合（比如带婴儿一天安排 3 个需要大量步行的景点）

【feasibility 可执行性】
5 = 时间安排现实，游览时长合理，三餐时间地点可行
3 = 有一两处不太现实的安排
1 = 根本走不完

先写理由，再打分。只输出一个 JSON 对象：
{"reason": "100 字以内的理由", "route": 1-5, "preference_fit": 1-5, "party_fit": 1-5, "feasibility": 1-5}"""


class JudgeScore(BaseModel):
    reason: str
    route: int = Field(ge=1, le=5)
    preference_fit: int = Field(ge=1, le=5)
    party_fit: int = Field(ge=1, le=5)
    feasibility: int = Field(ge=1, le=5)

    def normalized(self) -> dict[str, float]:
        """1~5 分 → 0~1，和规则评估器的分数放在同一个尺度上"""
        return {f"judge_{k}": (getattr(self, k) - 1) / 4 for k in ("route", "preference_fit", "party_fit", "feasibility")}


def plan_digest(plan: TripPlan) -> list[dict]:
    """给评委看的精简行程：只保留判断需要的信息（应对长度偏好，也省 token）"""
    return [
        {
            "date": day.date,
            "hotel": day.hotel.name if day.hotel else None,
            "attractions": [{"name": a.name, "address": a.address, "minutes": a.visit_duration} for a in day.attractions],
            "meals": [f"{m.type}:{m.name}" for m in day.meals],
        }
        for day in plan.days
    ]


def judge_plan(llm: BaseChatModel, request: TripRequest, plan: TripPlan) -> JudgeScore:
    user = (
        f"【用户需求】\n{request.model_dump_json(exclude={'start_date', 'end_date'})}\n\n"
        f"【行程】\n{json.dumps(plan_digest(plan), ensure_ascii=False)}"
    )
    text = llm.invoke([SystemMessage(JUDGE_SYSTEM_PROMPT), HumanMessage(user)], temperature=0).text
    # 评委的输出同样是"不可信输入"，复用第 7 课的思路：抠出 JSON 再用 Pydantic 校验
    start, end = text.find("{"), text.rfind("}")
    return JudgeScore.model_validate_json(text[start : end + 1])
```

**要点**

1. **rubric 给每个分数写清楚标准**，而不是"1-5 分，越高越好"。没有锚点的话，评委这次觉得"还行"给 4 分，下次给 3 分。
2. **先写理由再打分**（JSON 里 `reason` 放在最前面）：模型是从左到右生成的，先写理由相当于先"思考"，打分会更稳定。
3. **评委尽量用另一家的模型**。qwen 当评委给 qwen 打分，会有自我偏好。如果手里只有一家的 Key，至少用同一家更强的型号。
4. **评委也要被评测**：作业 3 让你自己给 10 条用例人工打分，和评委的分数对比，看它和你的判断一致到什么程度。一个和人类判断不一致的评委，分数再精确也没用。

## Step 7：评测主程序 `evals/run.py`

```python
"""评测主程序：在评测集上跑一遍规划图，计算每个用例的分数，输出汇总报告

用法：
  uv run python -m evals.run --variant baseline                       # 用 .env 里的模型
  uv run python -m evals.run --variant deepseek --model deepseek-chat \\
      --base-url https://api.deepseek.com --api-key-env DEEPSEEK_API_KEY
  uv run python -m evals.run --variant quick --limit 5                # 只跑前 5 条，调试用
  uv run python -m evals.run --variant baseline --judge               # 加上 LLM 评委
  uv run python -m evals.run --variant ci --min-success 0.9           # 成功率低于 90% 时退出码为 1（给 CI 用）
"""

import argparse
import json
import os
import statistics
import sys
import time
from concurrent.futures import ThreadPoolExecutor
from datetime import datetime
from typing import Any

from langchain_core.callbacks import get_usage_metadata_callback
from langchain_core.language_models import BaseChatModel
from langchain_openai import ChatOpenAI

from app.config import get_settings
from app.graph.state import PlannerDeps
from app.graph.trip_graph import trip_graph
from app.observability.logs import setup_logging
from app.observability.tracing import langchain_callbacks, score_trace, trace_span
from app.services.llm_service import get_llm
from evals.dataset import RESULTS_DIR, load_cases, load_context
from evals.evaluators import CaseOutput, evaluate
from evals.judge import judge_plan


def make_llm(model: str | None, base_url: str | None, api_key_env: str | None) -> BaseChatModel:
    """不传参数时用 .env 里的模型；传了就按参数创建，用来和别的模型做对比"""
    if not model:
        return get_llm()
    settings = get_settings()
    return ChatOpenAI(
        model=model,
        base_url=base_url or settings.llm_base_url,
        # os.environ[...]：从环境变量读取另一家的 Key，不要把 Key 写在命令行里（会留在 shell 历史记录中）
        api_key=os.environ[api_key_env] if api_key_env else settings.llm_api_key,
        timeout=settings.llm_timeout,
        max_retries=1,
    )


def run_case(case: dict[str, Any], llm: BaseChatModel, judge_llm: BaseChatModel | None, variant: str) -> dict[str, Any]:
    """跑一个用例，返回一行结果"""
    request, context = case["request"], load_context(case["id"])
    if context is None:
        raise SystemExit(f"用例 {case['id']} 没有冻结的 context，先运行 python -m evals.record_contexts")

    started = time.perf_counter()  # 高精度计时器，相当于前端的 performance.now()
    with (
        trace_span(f"eval/{case['id']}", tags=["eval", variant], input=request.model_dump(mode="json")) as span,
        # 统计这个 with 块里所有模型调用的 token 用量（按模型名分别累计）
        get_usage_metadata_callback() as usage_cb,
    ):
        final = trip_graph.invoke(
            {"request": request, "context": context},  # 带上冻结的 context，图会跳过 collect（P3 加的 route_start）
            config={"callbacks": [usage_cb, *langchain_callbacks()], "recursion_limit": 20},
            context=PlannerDeps(amap=None, llm=llm),  # 不会调用高德，所以 amap 传 None
        )
    latency = time.perf_counter() - started

    out = CaseOutput(request, context, final["plan"], final["source"], final.get("attempts", 0))
    scores = evaluate(out)
    judge_reason = None
    if judge_llm is not None and out.source == "llm":
        try:
            verdict = judge_plan(judge_llm, request, out.plan)
            scores |= verdict.normalized()  # |= 把评委的分数合并进来
            judge_reason = verdict.reason
        except Exception as exc:  # 评委自己也可能失败，不能因此丢掉整条结果
            judge_reason = f"评委失败: {exc}"

    # 把分数写回 Langfuse 的 trace：在界面上能按分数筛选，比如"找出所有 grounding < 0.8 的用例"
    if span is not None:
        for name, value in scores.items():
            if value is not None:
                score_trace(span.trace_id, name, value)

    usage = usage_cb.usage_metadata  # {"模型名": {"input_tokens": ..., "output_tokens": ...}}
    row = {
        "id": case["id"],
        "tags": case["tags"],
        "variant": variant,
        "source": out.source,
        "attempts": out.attempts,
        "latency_s": round(latency, 2),
        "input_tokens": sum(u["input_tokens"] for u in usage.values()),
        "output_tokens": sum(u["output_tokens"] for u in usage.values()),
        "scores": scores,
        "errors": final.get("errors", []),
        "judge_reason": judge_reason,
    }
    mark = "✅" if out.source == "llm" else "❌"
    print(f"{mark} {case['id']:<20} {latency:6.1f}s  尝试 {out.attempts} 次", flush=True)
    return row


def percentile(values: list[float], p: float) -> float:
    """第 p 百分位数，例如 p=95：95% 的请求都比它快"""
    ordered = sorted(values)
    return ordered[min(len(ordered) - 1, int(len(ordered) * p / 100))]


def summarize(rows: list[dict[str, Any]], price_in: float, price_out: float) -> dict[str, Any]:
    """汇总：每个指标取平均（跳过不适用的 None），再加上延迟和成本"""
    metric_names = rows[0]["scores"].keys()
    summary: dict[str, Any] = {"cases": len(rows)}
    for name in metric_names:
        values = [r["scores"].get(name) for r in rows if r["scores"].get(name) is not None]
        summary[name] = round(statistics.mean(values), 3) if values else None
    latencies = [r["latency_s"] for r in rows]
    summary["latency_p50_s"] = round(statistics.median(latencies), 1)
    summary["latency_p95_s"] = round(percentile(latencies, 95), 1)
    summary["avg_input_tokens"] = round(statistics.mean(r["input_tokens"] for r in rows))
    summary["avg_output_tokens"] = round(statistics.mean(r["output_tokens"] for r in rows))
    # 价格单位：元 / 百万 token
    summary["avg_cost_yuan"] = round(
        (summary["avg_input_tokens"] * price_in + summary["avg_output_tokens"] * price_out) / 1_000_000, 4
    )
    return summary


def main() -> None:
    parser = argparse.ArgumentParser()
    parser.add_argument("--variant", required=True, help="这次评测的名字，例如 baseline、qwen-max、prompt-v2")
    parser.add_argument("--model")
    parser.add_argument("--base-url")
    parser.add_argument("--api-key-env", help="存放 API Key 的环境变量名")
    parser.add_argument("--judge", action="store_true", help="启用 LLM 评委")
    parser.add_argument("--judge-model", help="评委模型，默认和被评测的模型相同（不推荐）")
    parser.add_argument("--judge-base-url")
    parser.add_argument("--judge-api-key-env")
    parser.add_argument("--ids", help="只跑这些用例，逗号分隔")
    parser.add_argument("--tags", help="只跑带这些标签的用例，逗号分隔")
    parser.add_argument("--limit", type=int)
    parser.add_argument("--workers", type=int, default=2, help="并发数，太大容易被模型供应商限流")
    parser.add_argument("--price-in", type=float, default=0.0, help="输入价格：元 / 百万 token")
    parser.add_argument("--price-out", type=float, default=0.0, help="输出价格：元 / 百万 token")
    parser.add_argument("--min-success", type=float, help="成功率低于这个值时，退出码为 1")
    args = parser.parse_args()
    setup_logging("WARNING")  # 评测时只看警告和错误，重试原因会显示出来

    split = lambda s: set(s.split(",")) if s else None  # noqa: E731
    cases = load_cases(ids=split(args.ids), tags=split(args.tags))[: args.limit]
    llm = make_llm(args.model, args.base_url, args.api_key_env)
    judge_llm = None
    if args.judge:
        judge_llm = make_llm(args.judge_model, args.judge_base_url, args.judge_api_key_env) if args.judge_model else llm

    print(f"🧪 评测 {args.variant}：{len(cases)} 个用例，并发 {args.workers}")
    with ThreadPoolExecutor(max_workers=args.workers) as pool:
        # pool.map 保持原来的顺序返回结果，相当于 Promise.all(cases.map(...))
        rows = list(pool.map(lambda c: run_case(c, llm, judge_llm, args.variant), cases))

    RESULTS_DIR.mkdir(exist_ok=True)
    out_path = RESULTS_DIR / f"{args.variant}_{datetime.now():%Y%m%d-%H%M%S}.jsonl"
    out_path.write_text("\n".join(json.dumps(r, ensure_ascii=False) for r in rows) + "\n", encoding="utf-8")

    summary = summarize(rows, args.price_in, args.price_out)
    print("\n| 指标 | 值 |\n|---|---|")
    for key, value in summary.items():
        print(f"| {key} | {value} |")
    print(f"\n结果已保存：{out_path}")

    if args.min_success is not None and summary["success"] < args.min_success:
        print(f"❌ 成功率 {summary['success']} 低于门槛 {args.min_success}")
        sys.exit(1)  # 非 0 退出码 = 失败，CI 会把这次构建标红


if __name__ == "__main__":
    main()
```

**要点**

1. **`get_usage_metadata_callback()`**：LangChain 自带的 token 统计回调，在 `with` 块里的所有模型调用都会被累计。它依赖模型返回里的 `usage_metadata` 和 `model_name`，所以要改一下假模型（Step 9）。
2. **分数写回 Langfuse**：如果配置了 Langfuse，每个用例的 trace 上都会挂着各项分数。评测发现某个用例 `grounding` 很低时，直接在 Langfuse 里点开它，看模型当时到底输出了什么。
3. **并发**：用线程池同时跑 2 个用例。`trip_graph` 是编译好的无状态蓝图，多个线程同时用没有问题（P1 讲过）。并发开太大会被模型供应商限流（HTTP 429），反而更慢。
4. **退出码**：`sys.exit(1)` 让 CI 知道"这次评测没过"。公司里常见的做法是：改了 `prompts.py` 的 PR，CI 自动跑一个小规模评测（比如 `--tags 常规 --limit 10`），成功率低于门槛就不允许合并。

```python
"""对比两次评测结果，输出 Markdown 报告

用法：uv run python -m evals.compare evals/results/baseline_xxx.jsonl evals/results/deepseek_xxx.jsonl
"""

import argparse
import json
from pathlib import Path

from evals.run import summarize


def load_rows(path: str) -> list[dict]:
    return [json.loads(line) for line in Path(path).read_text(encoding="utf-8").splitlines() if line.strip()]


def main() -> None:
    parser = argparse.ArgumentParser()
    parser.add_argument("baseline")
    parser.add_argument("candidate")
    parser.add_argument("--price-in-a", type=float, default=0.0)
    parser.add_argument("--price-out-a", type=float, default=0.0)
    parser.add_argument("--price-in-b", type=float, default=0.0)
    parser.add_argument("--price-out-b", type=float, default=0.0)
    args = parser.parse_args()

    rows_a, rows_b = load_rows(args.baseline), load_rows(args.candidate)
    a = summarize(rows_a, args.price_in_a, args.price_out_a)
    b = summarize(rows_b, args.price_in_b, args.price_out_b)
    name_a, name_b = rows_a[0]["variant"], rows_b[0]["variant"]

    print(f"## {name_a} vs {name_b}\n")
    print(f"| 指标 | {name_a} | {name_b} | 变化 |\n|---|---|---|---|")
    for key in a:
        va, vb = a[key], b.get(key)
        delta = f"{vb - va:+.3f}" if isinstance(va, (int, float)) and isinstance(vb, (int, float)) else ""
        print(f"| {key} | {va} | {vb} | {delta} |")

    # 逐个用例找"退步"：平均分可能掩盖个别用例的严重问题
    by_id = {r["id"]: r for r in rows_a}
    print("\n### 退步的用例\n")
    found = False
    for rb in rows_b:
        ra = by_id.get(rb["id"])
        if ra is None:
            continue
        for metric, vb in rb["scores"].items():
            va = ra["scores"].get(metric)
            if va is not None and vb is not None and va - vb >= 0.2:
                print(f"- `{rb['id']}` {metric}: {va:.2f} → {vb:.2f}")
                found = True
    if not found:
        print("（无）")


if __name__ == "__main__":
    main()
```

## 公司里的评测实践

| 实践 | 说明 |
|---|---|
| 离线评测 + 线上评测 | 本课是离线评测（固定数据集）。线上评测：从真实流量里抽样，用同样的评估器打分，盯趋势 |
| 评测集分层 | 冒烟集（10 条，每个 PR 跑）、回归集（全量，每天跑）、专项集（安全、长行程……） |
| 评测平台 | Langfuse Datasets、LangSmith、Braintrust 等都提供"数据集 + 实验对比"的界面，原理和本课一样 |
| 人工标注 | 定期抽样让人打分，校准 LLM 评委 |
| 先有评测，再优化 | 任何"我觉得这样改会更好"的想法，都要先有基线分数 |
