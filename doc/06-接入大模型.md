# 第 6 课：接入大模型（LangChain）

**目标**：用真实的大模型替换 mock，生成真正的行程。流程是"**先用代码调高德拿真实数据，再交给大模型做规划**"：

```
TripRequest
   │
   ├─① 代码调用高德：景点候选、酒店候选、餐厅候选、天气      （第 5 课的 AmapClient）
   │
   ├─② 拼成 prompt：用户需求 + 候选数据 + 输出格式要求
   │
   ├─③ llm.invoke([system, user]) → 大模型返回一条消息，取出文字
   │
   └─④ json.loads → TripPlan.model_validate → 返回前端
```

> 这其实已经是参考仓库最终架构（PlannerContext）的雏形：**工具调用由代码确定性地完成，大模型只负责规划**。书里的方案是让大模型自己决定调用哪些工具（第 8 课实现），第 9 课再对比两种方案的优劣。

对应：书 13.3，参考仓库 `backend/app/services/llm_service.py`、`app/agents/`。

> 本课代码用"假 LLM"（继承 LangChain 的 `BaseChatModel`，直接返回固定文本）和第 5 课的假高德数据测试过：合法 JSON 能正常解析；大模型自己算的 `budget.total` 会被丢弃，由后端重新计算；没配置大模型时自动退回 mock。**真实大模型调用需要你自己的 API Key。**

## Step 0：配置大模型

任选一个提供 **OpenAI 兼容接口**的服务，填进 `backend/.env`。下面是两个例子，模型名和地址以各平台文档为准：

```bash
# 例 1：DeepSeek
LLM_API_KEY=sk-xxxx
LLM_BASE_URL=https://api.deepseek.com/v1
LLM_MODEL_ID=deepseek-chat

# 例 2：阿里云百炼（通义千问）
# LLM_API_KEY=sk-xxxx
# LLM_BASE_URL=https://dashscope.aliyuncs.com/compatible-mode/v1
# LLM_MODEL_ID=qwen-plus
```

> "OpenAI 兼容"的意思是：接口路径和请求格式都和 OpenAI 一样（`POST {base_url}/chat/completions`），所以同一套代码改个地址就能换模型。前端类比：不同后端实现了同一份 REST 接口约定。

安装 LangChain 的 OpenAI 接入包：

```bash

uv add langchain-openai   # 会自动带上 langchain-core；讲义实测版本：langchain-openai 1.6.7 / langchain-core 1.6.6
```

> **为什么不用参考仓库的 hello-agents？** hello-agents 是书配套的教学框架，参考仓库用的就是它。本课程换成了业界更通用的 LangChain / LangGraph，**思路和书完全一样，只是 Agent 层的写法不同**。对照参考仓库时，看它"做了什么"，不要逐行对代码。

### LangChain 是一组包，不是一个包

| 包 | 作用 | 前端类比 | 哪一课用 |
|---|---|---|---|
| `langchain-core` | 基础抽象：消息（`SystemMessage` 等）、`BaseChatModel`、工具（`BaseTool`） | `@vue/runtime-core` | 第 6 课起 |
| `langchain-openai` | OpenAI 兼容接口的实现：`ChatOpenAI` | 一个具体的 adapter，比如 axios 的某个 adapter | 第 6 课起 |
| `langgraph` | 用"状态图"编排多步骤、多 Agent 流程 | 状态机库（XState） | 第 8 课 |
| `langchain` | 高层封装，比如开箱即用的 `create_agent` | 基于底层搭好的"全家桶" | 第 8 课 |

本课只需要前两个。**代码里依赖 `langchain-core` 的抽象，只在创建客户端的地方用到具体的 `ChatOpenAI`**，这样以后换模型厂商（Anthropic、Ollama……）或者测试时换成假模型，业务代码都不用改。

`app/config.py` 的大模型配置区追加一行：

```python
    llm_timeout: int = 180   # 单次大模型调用的超时（秒），生成多日行程比较慢
```

`.env.example` 里也补上 `LLM_TIMEOUT=180`。

## Step 1：`app/services/llm_service.py`

```python
"""大模型服务：创建并共享一个 ChatOpenAI 实例"""

from functools import lru_cache

from langchain_openai import ChatOpenAI

from app.config import get_settings


class LLMNotConfiguredError(Exception):
    """没有配置大模型 Key 时抛出"""


@lru_cache  # 单例：整个进程共用一个 LLM 客户端
def get_llm() -> ChatOpenAI:
    settings = get_settings()
    if not (settings.llm_api_key and settings.llm_base_url and settings.llm_model_id):
        raise LLMNotConfiguredError("LLM_API_KEY / LLM_BASE_URL / LLM_MODEL_ID 未配置完整")

    # 显式把配置传进去，而不是让 ChatOpenAI 自己去读 OPENAI_API_KEY 等环境变量：
    # 配置只有 config.py 一个来源，排查问题时不用猜"它到底读的是哪个变量"
    llm = ChatOpenAI(
        model=settings.llm_model_id,
        api_key=settings.llm_api_key,
        base_url=settings.llm_base_url,  # 任何 OpenAI 兼容接口都行：DeepSeek、通义、Kimi、本地 vLLM……
        timeout=settings.llm_timeout,
        # SDK 自带的重试：遇到 429 限流、5xx、网络抖动时自动重发（默认 2 次）
        # 设成 1：第 7 课我们会自己写"格式不合格就重试"的循环，两层重试叠加，最坏情况会等很久
        max_retries=1,
    )
    print(f"✅ LLM 初始化成功: model={llm.model_name}, base_url={settings.llm_base_url}")
    return llm
```

"""提示词：单独放一个文件，方便反复调整，也方便对比效果"""

# System Prompt：定义 Agent 的"人设"和输出格式，每次请求都一样
# 关键点：给出和 schemas.py 完全一致的 JSON 结构，大模型照着填，后端才能直接解析
PLANNER_SYSTEM_PROMPT = """你是专业的旅行规划师。根据用户需求和提供的候选数据，生成详细的旅行计划。

你必须只输出一个 JSON 对象，不要输出任何解释、Markdown 代码块标记或其他文字。
JSON 结构如下（字段名必须完全一致）：
{
  "city": "城市",
  "start_date": "YYYY-MM-DD",
  "end_date": "YYYY-MM-DD",
  "days": [
    {
      "date": "YYYY-MM-DD",
      "day_index": 0,
      "description": "当天行程概述，说明游览顺序和交通方式",
      "hotel": {"name": "酒店名", "address": "地址", "location": {"longitude": 116.39, "latitude": 39.90}, "estimated_cost": 400},
      "attractions": [
        {"name": "景点名", "address": "地址", "location": {"longitude": 116.39, "latitude": 39.90},
         "visit_duration": 120, "description": "景点介绍", "ticket_price": 60}
      ],
      "meals": [
        {"type": "breakfast", "name": "餐厅名", "estimated_cost": 30},
        {"type": "lunch", "name": "餐厅名", "estimated_cost": 60},
        {"type": "dinner", "name": "餐厅名", "estimated_cost": 80}
      ]
    }
  ],
  "weather_info": [
    {"date": "YYYY-MM-DD", "day_weather": "晴", "day_temp": 25, "night_temp": 15}
  ],
  "overall_suggestions": "总体建议",
  "budget": {"total_attractions": 0, "total_hotels": 0, "total_meals": 0, "total_transportation": 0}
}

规则：
1. 景点、酒店、餐厅优先从【候选数据】里选，name、address、location 必须原样复制，不要编造。
2. 每天安排 1-3 个景点和 breakfast/lunch/dinner 三餐，同一天的景点尽量在同一个区域。
3. 价格单位：ticket_price 是每人门票（元），meal.estimated_cost 是每人每餐（元），hotel.estimated_cost 是每间每晚（元）。
4. 所有价格和预算字段都必须是整数。
5. weather_info 只能使用【天气】里有的日期，没有数据的日期写 "day_weather": "暂无预报"，温度写 "未知"。
"""


def build_planner_prompt(request_json: str, candidates_json: str, weather_json: str, dates: list[str]) -> str:
    """User Prompt：每次请求的具体需求和数据"""
    # f-string 多行字符串：{变量} 会被替换，相当于 JS 的模板字符串
    return f"""请为下面的需求制定旅行计划。

【用户需求】
{request_json}

【行程日期】共 {len(dates)} 天：{", ".join(dates)}
days 数组必须正好 {len(dates)} 项，date 和 day_index 按顺序一一对应。

【候选数据】（来自高德地图）
{candidates_json}

【天气】（来自高德地图，可能只覆盖部分日期）
{weather_json}

只输出 JSON。"""
```

> **System Prompt 和 User Prompt 有什么区别？**
> 发给大模型的是一个消息数组 `[{role: "system", ...}, {role: "user", ...}]`。system 是"岗位说明书"，每次请求都一样；user 是"这一单的具体需求"。LangChain 里分别对应 `SystemMessage` 和 `HumanMessage`，大模型的回复是 `AIMessage`，下一步就会用到。

## Step 3：规划 Agent `app/agents/trip_planner.py`

````python
"""旅行规划 Agent：先查高德拿真实数据，再让大模型基于这些数据规划行程"""

import json
from datetime import timedelta

from langchain_core.language_models import BaseChatModel
from langchain_core.messages import HumanMessage, SystemMessage

from app.agents.prompts import PLANNER_SYSTEM_PROMPT, build_planner_prompt
from app.models.schemas import POIInfo, TripPlan, TripRequest
from app.services.amap_client import AmapClient


def compact_poi(poi: POIInfo) -> dict:
    """只保留大模型规划时需要的字段：字段越少，prompt 越短，速度越快、费用越低"""
    return {
        "name": poi.name,
        "address": poi.address,
        "district": poi.district,
        "location": poi.location.model_dump(),
        "rating": poi.rating,
        "cost": poi.cost,
    }


def trip_dates(request: TripRequest) -> list[str]:
    """行程中每一天的日期字符串"""
    return [(request.start_date + timedelta(days=i)).isoformat() for i in range(request.travel_days)]


class TripPlanner:
    # 类型写 BaseChatModel（抽象）而不是 ChatOpenAI（具体实现），类似 TS 里参数类型写 interface 而不是 class：
    # 只要是 LangChain 的聊天模型都能传进来，第 11 课测试时就传一个假模型
    def __init__(self, amap: AmapClient, llm: BaseChatModel):
        self.amap = amap
        self.llm = llm

    def collect_candidates(self, request: TripRequest) -> dict[str, list[dict]]:
        """第一步：调高德，收集景点、酒店、餐厅候选"""
        # 偏好作为景点搜索关键词；没选偏好就搜"景点"
        keywords = request.preferences or ["景点"]
        attractions: list[POIInfo] = []
        for keyword in keywords[:3]:  # 最多取 3 个偏好，避免调用次数太多
            attractions += self.amap.search_poi(keyword, request.city, limit=8)

        hotels = self.amap.search_poi(request.accommodation, request.city, limit=8)
        foods = self.amap.search_poi("美食", request.city, limit=15)

        # 不同关键词可能搜到同一个景点，用 dict 按 id 去重（后出现的覆盖先出现的）
        unique_attractions = list({poi.id: poi for poi in attractions}.values())
        return {
            "attractions": [compact_poi(p) for p in unique_attractions],
            "hotels": [compact_poi(p) for p in hotels],
            "foods": [compact_poi(p) for p in foods],
        }

    def plan(self, request: TripRequest) -> TripPlan:
        candidates = self.collect_candidates(request)
        weather = [w.model_dump() for w in self.amap.get_weather(request.city)]

        # ensure_ascii=False：中文按原样输出，否则会变成 北京，既浪费 token 又难读
        prompt = build_planner_prompt(
            request_json=request.model_dump_json(),
            candidates_json=json.dumps(candidates, ensure_ascii=False),
            weather_json=json.dumps(weather, ensure_ascii=False),
            dates=trip_dates(request),
        )
        print(f"📝 Prompt 长度: {len(prompt)} 字符")

        # 发给大模型的消息数组：[system 岗位说明书, user 这一单的需求]
        # 等价于 OpenAI 接口里的 [{"role": "system", ...}, {"role": "user", ...}]
        messages = [
            SystemMessage(PLANNER_SYSTEM_PROMPT),
            HumanMessage(prompt),
        ]

        # invoke 返回一个 AIMessage（大模型的回复消息），.text 取出其中的文字
        # temperature 越低输出越稳定；结构化输出一般用 0.2~0.5
        # 额外传给 invoke 的参数会原样放进这次请求的请求体，只对这一次调用生效
        response = self.llm.invoke(messages, temperature=0.3).text
        print(f"🤖 大模型原始输出（前 300 字）:\n{response[:300]}")

        # 最朴素的解析：直接当 JSON 读。大模型只要多说一句话、多套一层 ```json，这里就会失败。
        # 第 7 课专门解决这个问题
        data = json.loads(response)
        return TripPlan.model_validate(data)
````

### `invoke` 返回的是什么？

`self.llm.invoke(messages)` 返回的不是字符串，而是一个 `AIMessage` 对象，常用的字段有：

```python
AIMessage(
    content='{"city": "北京", ...}',   # 回复内容
    usage_metadata={"input_tokens": 3021, "output_tokens": 1850, "total_tokens": 4871},  # token 用量（作业 1 会用到）
    response_metadata={"model_name": "deepseek-chat", "finish_reason": "stop", ...},
)
```

`.text` 是一个属性，用来取出回复里的纯文字。有些模型的 `content` 不是字符串，而是一个"内容块"列表（文字、图片、思考过程……），`.text` 会把其中的文字拼好再返回，所以优先用 `.text`，不要直接用 `.content`。

> `finish_reason` 值得留意：`"stop"` 表示模型正常说完了；`"length"` 表示输出达到长度上限被**截断**了，这正是下一节"你大概率会遇到的失败"里的最后一种情况。

from app.agents.trip_planner import TripPlanner

def get_trip_planner() -> TripPlanner | None:

## Step 5：路由 `app/api/routes/trip.py`（整个文件替换）

```python
"""旅行规划相关接口"""

from fastapi import APIRouter, Depends, HTTPException

from app.agents.deps import get_trip_planner
from app.agents.trip_planner import TripPlanner
from app.config import get_settings
from app.models.schemas import TripPlanResponse, TripRequest
from app.services.mock_planner import build_mock_plan

router = APIRouter(prefix="/trip", tags=["旅行规划"])


@router.get("/health", summary="旅行规划健康检查")
def trip_health():
    settings = get_settings()
    return {
        "status": "healthy",
        "service": "trip-planner",
        "amap_configured": bool(settings.amap_api_key),
        "llm_configured": bool(settings.llm_api_key),
    }


# def 而不是 async def：Agent 内部的高德调用和大模型调用都是同步阻塞的（见第 5 课的表格）
@router.post("/plan", response_model=TripPlanResponse, summary="生成旅行计划")
def plan_trip(
    request: TripRequest,
    # 依赖注入：没配大模型时拿到的是 None
    planner: TripPlanner | None = Depends(get_trip_planner),
):
    if planner is None:
        plan = build_mock_plan(request)
        return TripPlanResponse(success=True, message="未配置大模型，返回 mock 数据", data=plan)

    try:
        plan = planner.plan(request)
    except ValueError as exc:
        # json.JSONDecodeError 和 Pydantic 的 ValidationError 都是 ValueError 的子类
        # 也就是"大模型输出的不是合法 JSON"或"JSON 结构不符合 TripPlan"
        raise HTTPException(status_code=500, detail=f"大模型输出无法解析: {exc}") from exc

    return TripPlanResponse(success=True, message="旅行计划生成成功", data=plan)
```

### 你大概率会遇到的失败

多试几次，迟早会看到这个错误：

```
大模型输出无法解析: Expecting value: line 1 column 1 (char 0)
```

去终端看大模型的原始输出，通常是下面几种情况之一：

- 开头多了一句"好的，这是您的行程："
- JSON 被包在 ```` ```json ... ``` ```` 代码块里
- 天数不对、日期错位、少了一顿饭
- 输出太长被截断，JSON 不完整

**这是正常现象，不是你代码写错了**：大模型的输出本质上是概率采样的结果，prompt 写得再好也不能保证 100% 符合格式。下一课专门解决这个问题。
